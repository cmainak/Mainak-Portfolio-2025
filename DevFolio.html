PORTFOLIO REDESIGN

I built my portfolio website from scratch using Semantic HTML, CSS, and Vanilla JavaScript. The live site runs on Netlify, and I manage the source code through GitHub.

95+ Lighthouse Score
0 External Libraries
4 Custom JS Features
ROLE Designer & Developer
TIMELINE 18 weeks
TOOLS HTML, CSS, JS
PLATFORM Responsive Web

The Problem

Designing for myself instead of my audience resulted in severe information overload. Complex micro-interactions, erratic floating background objects, and unnecessary background details created a heavy cognitive load for busy hiring managers who only have seconds to skim a profile. Under the hood, the initial codebase was a chaotic mess of nested <div> tags built while learning to code, resulting in a poor Lighthouse accessibility score of 60.

The Solution

I stripped away the fluff and pivoted to a clean, minimal, outcome-focused structure that respects the user's time. I moved primary projects to the top, removed visual noise, and replaced the structural layout with a clean CSS Grid system. By writing raw Vanilla JS and semantic HTML, I achieved the exact same visual design with a fraction of the codebase and fully compliant accessibility.

Refactoring the "Div Soup"

My first successful build was a chaotic mess of nested tags used to force elements into alignment. I replaced the entire layout with a clean CSS Grid system and strict semantic HTML, achieving the exact same visual design with a fraction of the codebase.

Writing Vanilla JavaScript

I wrote raw JavaScript instead of loading external libraries. The code handles four main features, avoiding heavy frameworks like React for simple state changes.

Mobile Menu Toggle

Opens and closes the navigation drawer on small screens.

Dark Mode Switch

Swaps CSS color variables and saves the user's choice to local storage.

Project Gallery

Filters portfolio items using data attributes.

Form Validation

Checks inputs in the browser to block empty or broken email submissions.

Production Snippet: Non-blocking Theme Initialization

To prevent a flash of unstyled content, this script checks local storage and the browser OS preference before the DOM paints. 

(function () {
  try {
    const saved = localStorage.getItem('color-scheme');
    const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
    const theme = saved || (prefersDark ? 'dark' : 'light');
    document.documentElement.setAttribute('data-theme', theme);
  } catch(e) {}
})();

Visual Pivot & Accessibility Turnaround

The first Google Lighthouse audit returned a score of 60 due to W3C standards failures, poor text contrast, and missing keyboard states. I systematically fixed these issues, redesigned for scannability, and boosted the score to 95+.

Before (Lighthouse 60)

Severe information overload, erratic micro-interactions, and accessibility failures.

After (Lighthouse 95+)

Clear typographic hierarchy, eliminated visual noise, and compliant keyboard tracking.

Before (Div Soup Code)

Chaotic, non-semantic DOM structure causing screen reader failures.

After (Semantic HTML)

Strict architectural tags passing W3C validation instantly.

Continuous Deployment: The site uses an automated pipeline. When I push a commit to the main branch on GitHub, a Netlify webhook triggers and updates the live site in seconds without manual server work.
