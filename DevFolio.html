PORTFOLIO REDESIGN

I built my portfolio website from scratch using Semantic HTML, CSS, and Vanilla JavaScript. The live site runs on Netlify, and I manage the source code through GitHub.

95+ Lighthouse Score
0 External Libraries
4 Custom JS Features
ROLE Designer & Developer
TIMELINE 18 weeks
TOOLS HTML, CSS, JS
PLATFORM Responsive Web

The Problem

I originally designed the site for myself rather than hiring managers. I placed heavy background details at the top of the page and added floating animations. This visual noise delayed task completion and broke accessibility standards.

The Solution

I deleted the animations and moved my main projects to the top. The new layout lets recruiters scan my technical skills immediately.

Refactoring the code

I started this project in a Master's class before I knew how to code. Since I learned HTML and CSS by trial and error, my first working layout relied on a massive stack of nested <div> tags.

Once the page looked right, I deleted the extra containers and rebuilt the structure using CSS Grid. I reorganized the file directory and added comments. The site now looks exactly the same but runs on much less code.

Writing Vanilla JavaScript

I wrote raw JavaScript instead of loading external libraries. The code handles four features:

Mobile Menu Toggle

Opens and closes the navigation drawer on small screens.

Dark Mode Switch

Swaps CSS color variables and saves the user's choice to local storage.

Project Gallery

Filters portfolio items using data attributes.

Contact Form Validation

Checks inputs in the browser to block empty or broken email submissions.

Production Snippet: Non-blocking Theme Initialization

To prevent a flash of unstyled content, this script checks local storage and the browser OS preference before the DOM paints. 

(function () {
            try {
              const saved = localStorage.getItem('color-scheme');
              const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
              const theme = saved || (prefersDark ? 'dark' : 'light');
              document.documentElement.setAttribute('data-theme', theme);
            } catch(e) {}
          })();

Fixing accessibility and deployment

The first Google Lighthouse audit returned a score of 60. The layout failed W3C standards for text contrast and keyboard navigation.

I fixed these WCAG failures by replacing generic containers with semantic layout tags, adding ARIA labels to the JavaScript features, and making every button keyboard accessible. The Lighthouse score now sits above 95.

The site uses an automated deployment pipeline. When I push a commit to the main branch on GitHub, a Netlify webhook triggers and updates the live site in seconds without manual server work.
